# PixFilter

PixFilter 是一个纯本地的图片重复/相似检测工具：先按 MD5 找出完全相同的文件，再用 pHash 找出视觉上相近的图片，最后把多余的副本移动到扫描目录下的 **`重复文件`** 文件夹。

当前版本：**v1.0.3**（PySide6 桌面界面）。所有处理都在本机完成，不联网、不上传图片。

## 核心红线

- **纯本地运行**：不请求网络、不上传任何图片；GitHub 按钮只是打开项目主页。
- **绝不删除原文件**：移动只用 `shutil.move`，把重复/相似图片搬进 `重复文件`，不会调用删除 API。
- **保持相对目录结构**：`a/b/1.jpg` 会移动到 `重复文件/a/b/1.jpg`；目标已存在时自动加 `_1`、`_2` 后缀，绝不覆盖。
- **空目录才清理**：只有“全量撤销”把所有文件移出、且 `重复文件` 已经为空时，才用 `os.rmdir` 删除这个空文件夹；任何失败都只提示，不强行删除。
- **不扫描回收站**：扫描时会跳过 `重复文件` 目录，也不允许把它本身选作扫描目录。

## 功能一览

### 扫描与识别

- 支持 `.jpg` / `.jpeg` / `.png`（大小写不敏感）。
- 第一阶段按 MD5 分组，找出内容完全相同的文件。
- 第二阶段对每个“内容保留一张”的代表图计算 pHash（默认 8×8，64 位），用汉明距离聚类视觉相似图片；完全重复的副本不再重复解码。
- MD5 与 pHash 均使用多线程并发计算，扫描过程有进度条与两阶段日志；可随时点击“停止”。
- 阈值滑块范围 **1–20**，默认 **8**：数值越小越严格，只把更接近的图片判为相似。
- 无法读取、解码失败或内存不足的图片会记录警告并跳过，不影响其余文件。

### 批量复核工作台

扫描发现待确认分组后，会自动打开批量复核工作台：

- **左侧**：纯文本分组列表（显示序号/总数、处理状态、前两张文件名与体积、总张数），不加载缩略图，滚动流畅。
- **右侧**：当前组的卡片式并排对比，只加载当前组的图片。
- 处理完一组后自动前进到下一组；全部处理完显示汇总页，仍可用“撤销本组”回退最近处理过且有可撤批次的一组。
- **跳过**：放弃本组，不移动任何文件。
- **保留选中的，移动其他图片**：点击卡片可切换要保留的那一张；默认 keeper 规则为：
  - 完全重复组：按路径排序取第一张；
  - 相似组：分辨率最高 → 体积最大 → 路径排序。
- **两张都不要，全部移入重复文件**：整组丢弃，红色警告按钮，二次确认框会显示本组真实张数。
- **撤销本组**：只还原当前这一组之前移动的文件；不影响其他组、也不影响全局撤销栈中的其他批次。
- 直接点窗口 X / Esc 关闭：未决策的组会以“挂起”状态回到主界面的待处理列表，不移动文件。

### 主界面

- **全量撤销移动**：按批次倒序（LIFO）把撤销栈里的所有文件搬回原路径；单个文件失败只记录警告并继续，全部处理完后清空撤销栈、待处理组与复核状态，`重复文件` 为空时删除该文件夹。
- **待处理重复组表格**：列出挂起/未完成的分组，支持“继续处理”“放弃处理选中组”“全部放弃”（全部放弃有二次确认，不移动文件）。
- **Toast 提示**：扫描完成等关键节点在窗口顶部做非阻塞提示。
- **复制日志路径**：日志中的扫描目录可点击复制。
- **打开重复目录**：扫描产生 `重复文件` 后，可一键用系统文件管理器打开。
- **GitHub 按钮**：打开项目主页 `https://github.com/4revo/PixFilter`。

## 相似分组性能

pHash 聚类使用**鸽巢分块索引**：

- 段数 = 阈值 + 1（阈值 8 即 9 段）。把 64 位哈希切成连续块，Hamming 距离 ≤ 阈值时，必然至少有一段完全相同，因此只需在同段内比较候选。
- 候选对再用并查集合并，得到传递闭包分组（A 相似 B、B 相似 C，则 A/B/C 同组）。
- 结果与原“全量两两比对”完全等价；测试对多种阈值和数据规模断言两种策略的分组结果一致。

以下情况自动退回全量比对，避免索引反而变慢：

- 参与聚类的图片少于 **50** 张；
- 阈值大于 **15**（所需段数超过 16）；
- 估算候选对数量达到总对数的 **50%** 及以上。

开发机一次实测（1100 条合成 pHash、阈值 8）：全量比对 **93–99 ms**，鸽巢分块 **22–24 ms**，约 **4.3×**。该数字只反映聚类阶段；扫描总耗时仍主要受图片解码、MD5 与 pHash 计算限制，“大量小图”场景提升有限。

## 安装与运行

环境要求：

- Windows 桌面环境；
- Python **3.10+**；
- PySide6、Pillow、ImageHash（见 `requirements.txt`）。

```bash
pip install -r requirements.txt
python main.py
```

## 使用流程

1. 点击“点击此处选择扫描文件夹”，选择一个目录。
2. 按需调整相似阈值（默认 8）。
3. 点击“开始扫描”，等待 MD5 与 pHash 两阶段完成。
4. 扫描发现分组后自动进入批量复核工作台，逐组选择保留项或整组丢弃。
5. 关闭工作台后，未处理的组会出现在主界面“待处理重复组”表格中，可稍后继续或放弃。
6. 需要回滚时：
   - 工作台内用“撤销本组”只还原当前组；
   - 主界面用“全量撤销移动”还原本次运行的所有移动。

## 撤销与文件安全

- 撤销栈**只保存在内存**，程序退出即清空，重启后无法撤销上一次运行。
- 全量撤销会清空所有批次、挂起组与复核状态；之后可以重新选择文件夹扫描。
- 还原时如果原路径已被同名文件占用、回收站文件已缺失、文件被占用或权限不足，会记录警告并跳过该文件，其余文件继续还原。
- 还原只做 `shutil.move` 回原路径，不会覆盖已有文件，也不会删除回收站中的内容；失败的副本仍保留在 `重复文件` 里。

## 打包

提供两个互不干扰的 PyInstaller 脚本，分别使用独立的 spec 与构建目录：

| 脚本 | 方式 | 产物 | 适用场景 |
|---|---|---|---|
| `build_onefile.bat` | `--onefile` | `dist/PixFilter_v1.0.3.exe` | 单文件分发，直接发给他人 |
| `build_onedir.bat` | `--onedir` | `dist_onedir/PixFilter_v1.0.3_folder/`（含 `_internal` 依赖目录） | 日常使用，启动更快，必须整个目录分发 |

- `build_onefile.bat` 只清理 `build/` 与同版本 exe，保留 `dist/` 中其他版本文件；`build_onedir.bat` 只清理 `build_onedir/` 与该版本的 onedir 目录，不触碰 `dist/`。
- 两者生成的中间 spec 分开存放，不会互相删除；仓库内的 `PixFilter.spec` 与 `PixFilter_onedir.spec` 分别对应两种打包方式。
- 两个 `.bat` 的注释全部使用英文：CMD 在 GBK 代码页下读取中文注释容易报错。
- onefile 首次启动需要自解压，速度较慢；onedir 无此开销。PySide6 依赖体积较大，两种产物都不算小。

## 已知限制与安全说明

- 撤销栈、挂起组只存在内存中；关闭程序后无法恢复上一次运行的状态。
- pHash 基于整图感知哈希，不做裁剪、旋转、镜像或局部匹配；极端改色/叠加文字可能漏检。
- 相似分组使用传递闭包，链式相似的图片可能被合并进同一组，请复核后再移动。
- 只处理 `.jpg` / `.jpeg` / `.png`；GIF、WebP、HEIC 等格式不会被扫描。
- 超大图不会被统一跳过：不做像素上限拦截，JPEG 在计算 pHash 前会用 `draft()` 降采样；只有真正无法解码或内存不足的图片才会记录警告并跳过整张。
- `重复文件` 不会自动清空；除“全量撤销”后按需删除空目录外，其余时候需要用户自行整理。
- 扫描目录应当是可信的本地目录；程序会并发读取其中所有支持格式的图片。
