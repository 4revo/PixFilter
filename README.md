# PixFilter

纯本地运行的照片去重桌面工具：扫描一个文件夹，找出**完全重复**（MD5）与**视觉相似**（pHash）的图片。每组都会弹出并排对比窗口，由你确认保留哪一张；只有点击主操作后，其余图片才会被移动到扫描目录下的 `重复文件`。

对比窗口的「跳过」是一次性放弃；点窗口 X 则是**挂起**：该组会完整保留到主界面「待处理重复组」面板，之后仍可继续处理。

- 不联网、不上传
- 只移动，不删除（全项目没有删除语义的调用，只使用 `shutil.move`）
- `重复文件` 内保留原相对目录结构；文件名冲突自动加 `_1`、`_2` 后缀，绝不覆盖
- 再次扫描时自动跳过 `重复文件`

## 安装与运行

需要 Python 3.10+ 与 PySide6（见 requirements.txt），无需额外的系统 GUI 库。

```powershell
pip install -r requirements.txt
python main.py
```

## 使用

1. 点击左上角的「点击此处选择扫描文件夹」。按钮文字不会变化，选中的绝对路径会打印在扫描日志里。
   - 日志中的 `当前扫描目录：<路径>（左键点击复制）` 是蓝色下划线文本，左键点击即可把纯路径复制到剪贴板，并追加「✅ 路径已复制到剪贴板」。
   - 多条目录行各自独立可点；路径包含空格、中文、括号也按原样复制。
2. 按需拖动「相似阈值」滑块（范围 1–20，默认 8）；右侧会实时显示「当前: N」，扫描使用该整数阈值。
3. 点击「开始扫描」。
4. 每发现一组重复/相似图片，会弹出确认窗口：
   - 组内图片横向并排，超出宽度时可水平滚动（也支持鼠标滚轮）。
   - 每张缩略图最大 300×300 且严格保持原比例，下方显示文件名、分辨率、文件大小。
   - 默认选中「分辨率最高 → 体积最大 → 路径排序」的那张（完全重复组按路径排序）。
   - 状态提示会标出「✓ 当前将被保留」与「→ 确认后移入“重复文件”」。
   - 点击任意缩略图可打开高清大图窗口（最大为屏幕 80%，等比缩放）；按 `Space` 或 `Esc` 关闭并释放图像引用。
5. 点击「保留选中的，移动其他图片」才会执行移动；点击「跳过」= 本次放弃该组（不移动）；点窗口 X = 挂起，不移动并保留到主界面「待处理重复组」。
6. 主界面日志下方的「待处理重复组」列表会显示组号、类型、张数与概要：
   - 选中一行（默认选中第一行）后点「继续处理」重新打开同一个对比窗口；双击该行也可直接继续。
   - 「继续处理」中再次点 X，该组仍留在列表，不会丢失，也不会循环。
   - 选中后点「放弃处理」会明确丢弃该组：不移动任何文件，并在日志中记录被放弃的文件路径。
7. 全部处理完（或没有待处理组）时，主窗口顶部中央会滑出「扫描完成！」绿色圆角提示条（约 200×40，长文案自动加宽至主窗口宽 90% 上限；滑入约 120ms、停留 1.5 秒、原地淡出约 400ms，位置每次按主窗口实时坐标重新计算）；若仍有挂起组，提示会写成「扫描完成，还有 N 组待处理」，与状态栏一致。
8. 到 `<扫描目录>/重复文件` 中检查并手动还原误移出的文件。

扫描与逐组确认期间，「开始扫描」按钮保持禁用；「停止」随时可用。停止后不再弹出新组，已经弹出的那一组仍按你的选择处理完。

只要还有挂起组，「开始扫描」就保持禁用（不会静默丢弃挂起数据）；需要重新扫描时，请先「继续处理」或「放弃处理」清空列表。若挂起期间某些文件已被其他组的操作移走，继续处理时会记日志并跳过缺失项，不会崩溃；若保留项缺失，则本组不移动任何文件并留在列表。

## 判定规则

- 只处理扩展名不区分大小写的 `.jpg`、`.jpeg`、`.png`。
- **精确重复**：按文件 MD5 分组，默认保留路径排序第一张。
- **视觉相似**：对每个内容保留一张代表图计算 pHash（`hash_size=8`，64 位），用汉明距离聚类；先用「鸽巢分桶」粗筛候选，再做精确距离比较，避免全量 O(n²)。
- 相似组默认保留**分辨率最高**的一张；分辨率相同取文件体积最大；再相同取路径排序第一。
- 默认选中项与上述保留规则完全一致（直接复用核心模块的 `pick_default_keeper`）。
- 无法读取 / 无法解码的图片会记录告警并跳过，不影响其余扫描。
- 移动使用 `shutil.move`，失败时保留原文件并记录错误，不会导致文件消失。
- 组内只剩一张图片时不会弹出确认窗口。

## 阈值说明

`8` 是比较稳妥的默认值：通常能覆盖缩放、重新压缩、轻微调色的副本；调到 `12` 以上会开始把“构图相近但内容不同”的照片合并，建议先用小目录试验。`0` 表示只接受 pHash 完全一致。

## 线程与界面

- 所有文件扫描与移动在工作线程中执行；所有 Tk 控件创建、`wait_window` 和图片显示只在主线程执行。
- 工作线程通过 `queue.Queue` 提交待确认组与日志；主线程用 `root.after` 轮询、弹窗并等待决策。
- 工作线程通过阻塞式 `Queue.get()` 等待用户决策，不空转、不占用 CPU。
- 关闭主窗口时，如果确认窗口尚未处理完，会按「挂起」返回并干净退出；已存在的 Toast 会取消其全部未执行的 `after` 回调后销毁，不会残留或抛出 `TclError`。
- 扫描完成提示由 `root.after` 递归驱动滑入/停留/滑出，不阻塞主线程（没有 `wait_window` / `sleep`）；连续触发会替换旧提示并取消旧回调，不会叠加。
- 日志 Text 始终只读，写入时临时切到 `normal` 再恢复 `disabled`；路径点击使用每个目录行独立的 tag 绑定，不依赖全局点击。

## 已知限制

- 「待处理重复组」保存在当前进程内存中：关闭应用后不会恢复，如需保留请先处理完再退出。
- 挂起组只记录扫描时的成员信息；继续处理时若文件已被其他组移走，会明确记录「文件不存在」并跳过该缺失项，不会移动剩余项之外的文件。
- 相似聚类使用传递闭包（并查集），极端情况下 A≈B、B≈C 但 A 与 C 的距离可能超过阈值，仍会被归为一组。
- 相似组按规则默认保留最高分辨率的那张，因此若“低分辨率原图的放大版”也在同一组，默认选中的会是放大版（可在弹窗中手动改选）。
- 完全重复组与相似组可能重叠：此时两组会分别确认，后确认的相似组可能把前一组刚保留的图片移入 `重复文件`。
- 只比较整图 pHash，不识别裁剪、旋转、镜像或局部修改。
- pHash 基于灰度结构，因此“构图相同但颜色/背景不同”的图片可能被判为相似，可调低阈值减少误合并。
- 动图（GIF/WebP/HEIC 等）不在支持范围内。
- `重复文件` 不会自动清理，需要用户自行确认后手动处理。
